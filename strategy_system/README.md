# 策略研究系统 v0.1

用途：将策略规则、资金约束、条件成交、逐笔账本、独立回放与结论分开。只读历史数据，不联网、不轮询、不下单。当前已实现的是现货研究基线，合约策略系统仍未完成。

## 已实现

- 固定策略：BTC/ETH 的小时收盘突破此前24小时最高价入场，跌破此前4小时最低价退出；下一小时开盘价格加成本代理成交。
- 资金：2000 USDT 组合，400储备，每币最大800；同一时点多个入场共享可用资金。
- 费用：买入扣基础币、卖出扣报价币，含交易精度、余量与拒绝处理；持有对照使用同成本、同资金分配。
- 基础、加倍手续费、20bps滑点、额外1小时延迟四个情景全部输出，未自动挑最好结果。
- 原始文件哈希和逐日OHLCV核对；缺失小时、错误产品、未闭合K线等拒绝运行。
- 第二实现独立计算信号、成交、现金、库存、待处理订单、权益和指标；逐项比较。
- 每轮新建输出目录，冻结规则与代码哈希；不可覆盖同名试验。失败留下failure.json，成功须receipt.json存在。

## 运行

在项目根目录执行：

```sh
python3 -m unittest discover -s strategy_system -v
python3 strategy_system/system.py retest --out research/strategy-system-20260930/你的唯一试验名
python3 strategy_system/system.py futures-gate
```

所有路径由项目根目录解析，历史引擎原文件未修改。依赖仅Python标准库及仓库内已存在的研究代码。freeze.json明确记录后者绝对路径与哈希；移动/删除原资料会导致不可运行，不能悄悄替换数据。

## 验收含义

测试通过表示软件与条件账本一致，不代表收益有效。所有现存历史已经用于探索，不能称独立样本外；此次复测不产生新统计证据。报告保留全部情景、亏损、回撤及相对持有表现，现金收益对照为0。

下一阶段必须先固定候选，再封存真正未见的连续验证期和通过/失败标准，记录所有试验次数。不允许根据验证结果换窗口、改币种、翻转方向，再把同一数据叫验证。

## 合约通道的真实缺口

目前BLOCKED，不允许把现货收益乘杠杆。需真实SWAP行情、时点有效合约规格、资金费结算记录、标记价格路径、保证金阶梯与强平/退出处理，以及对应第二实现。小时OHLC不能唯一还原柱内强平先后；无法判定时必须UNKNOWN，不能补造有利路径。成交延迟、拒绝与深度模型也需单独验证。

## AI与Skills

本轮使用backtesting-frameworks的偏差控制、成本和独立验证原则；typesafe-ai用于明确语义判断与代码计算边界，没有调用TypeSafe API。TradingAgents全流程尚未接入；不将普通突破策略或一次ETH方向观察标为TradingAgents结果。AI以后只能生成有时间戳、输入来源、模型版本的候选判断，由统一账本评估；模型费用也应记录。HyperFrames是展示工具，不作为收益验证组件。

旧150u-24轮询保持暂停；本系统没有自动任务或实盘入口。
